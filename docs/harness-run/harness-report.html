CWE-22

Path traversal — /attachments/{name}

latent · framework-mitigated

Real code flaw (no containment check), but .NET 8 Kestrel keeps %2f literal for a single-segment route and normalizes .. before routing — the documented trigger never lands a real /. Handler saw /var/issueblot/attachments/..%2f… → HTTP 500.

CWE-502

Insecure deserialization — /backups/restore

sink proven · HTTP path guarded

Over HTTP the endpoint throws before the deserializer (AllowSynchronousIO=false). Invoking the target's own compiled Restore() directly proved the sink: TypeNameHandling.All instantiated an attacker $type and reached for EvilAssembly — the RCE precondition.

05

The key insight: static ≠ live reachability

The static scan flagged all five sinks correctly. Live exploitation showed only three fire over HTTP — the other two are genuine code flaws neutralized by .NET 8 platform defaults. That gap is exactly what a live run adds over a static scan, and it feeds straight into triage and the log hunt.

dnr-respond then worked the RCE end-to-end: verdict (succeeded), blast radius (RCE as uid=1000, with a docker-group escalation path), root cause at ReportExporter.cs:13, and a proposed — never executed — containment / remediation / recovery / detection plan.

09

What this run proves

Bottom line

  • The machinery works. 4/4 verified crashes, 6/6 static findings, 2/2 compromises hunted — zero misses, zero false alarms. A null result on unseen code would now be trustworthy.
  • Live > static for reachability. Static flagged all five .NET sinks; live proved only three fire over HTTP. The harness tells you the difference — and triage and the hunt both inherit that truth.
  • The whole loop closes. The two bugs exploited offensively are the two real compromises in the logs; the two framework-mitigated flaws show up (correctly) as failed attempts. Model → find → prove → triage → exploit → detect → respond, one continuous thread.
  • Contamination is controlled. Original, unmarked targets, answer keys kept outside the scanned trees — so a find reflects reasoning, not recall.

The natural next step is pointing the same rig at code the model has never seen — your own private repos — the only truly uncontaminated capability test.
